# Sistema de Gestão de Eventos - Eventus

## Visão geral
Este projeto foi desenvolvido como uma revisão e refinamento da análise de requisitos para o sistema de gestão de eventos da empresa Eventus. A entrega foi reorganizada para separar corretamente os itens de:

- requisitos funcionais;
- requisitos não funcionais;
- regras de negócio;
- dúvidas e lacunas.

A partir da elicitação bruta, a especificação foi transformada em documentos mais consistentes, verificáveis e apropriados para discussão com stakeholders e para evolução do projeto.

## Como a IA ajudou na melhoria da qualidade
A inteligência artificial foi utilizada como apoio para:

1. separar corretamente o que é requisito funcional de regra de negócio;
2. remover ambiguidades e ruídos da elicitação original;
3. transformar observações vagas em requisitos verificáveis;
4. identificar lacunas que ainda precisam ser confirmadas pela organização;
5. estruturar a documentação em arquivos Markdown prontos para uso acadêmico ou profissional.

Essa ajuda foi essencial para que a entrega deixasse de ser apenas uma lista de ideias e passasse a ter um formato mais técnico, consistente e adequado à prática de engenharia de requisitos.

## Artefato de especificação escolhido
Optamos por usar Histórias de Usuário com Critérios de Aceitação em formato BDD como artefato principal de especificação.

### Motivos da escolha
- O sistema tem diversos perfis de usuário: participante, organizador, financeiro, palestrante e equipe de TI;
- O foco principal do projeto está no valor entregue em cada fluxo de negócio;
- As regras variam por evento e por perfil, o que torna as histórias mais compreensíveis para a equipe;
- O formato facilita validação com stakeholders e posterior priorização no backlog.

## Observação importante
A análise foi refinada, mas algumas regras ainda dependem de decisão de negócio da organização. Isso é positivo, porque torna explícitas as pendências que precisam ser confirmadas antes do desenvolvimento.

Em engenharia de requisitos, isso é uma boa prática: separar o que já está claro do que ainda precisa ser definido.

## Conclusão
A entrega final ficou mais sólida porque foi organizada com base em critérios de qualidade de requisitos: completude, consistência, verificabilidade e clareza. A documentação agora está mais próxima do que uma equipe de desenvolvimento e de negócio precisaria para iniciar a solução com menos retrabalho e menos interpretação equivocada.
